## 2. Logic Chain

1. **Source Discovery**: We inspected all route files, controllers, services, repositories, and Zod validation schemas across `course`, `exam-category`, `test`, `test-series`, `quiz`, `aiQuiz`, `enrollment`, `payment`, `coupon`, `review`, `admin`, and `settings` modules.
2. **Contract Traceability**: We mapped every endpoint's URI, HTTP method, required authentication middleware (`authenticate`, `authorize`, `optionalAuth`, `requireTenant`, `optionalTenant`), input parameters (path, query, body), and response formats.
3. **Data Access Mapping**:
   - In Mongoose architecture, models were defined in `*.model.ts`/`*.model.js` files and queried via Mongoose queries or repositories.
   - In Prisma target architecture, models correspond to `User`, `Institute`, `Category`, `Course`, `Lesson`, `Enrollment`, `Test`, `TestAttempt`, `Quiz`, `QuizAttempt`, `Payment`, `Review`, `Blog`, `Coupon` in `server/prisma/schema.prisma`.
   - The query contracts (e.g. `prisma.course.findMany`, `prisma.testAttempt.create`, `prisma.enrollment.upsert`, etc.) provide 1:1 behavioral parity with the discovered features and edge cases.
4. **Behavioral Integrity**: We traced the core business logic (e.g. course lesson drip locking, proctoring violation auto-submission at 5 violations, objective answer evaluation with negative marking, 100% coupon checkout bypass, Razorpay HMAC signature verification, certificate generation on completed courses) so that tests in Tiers 1-4 can assert exact, verifiable expectations.
